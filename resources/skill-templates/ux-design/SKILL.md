# UX 设计

## 工作流程

1. 读取 `.workspace/project-context.json`，确认当前项目目录、`uiAssets`、`knowledgeBase` 和可写范围。
2. 明确目标页面、用户任务、关键状态、交互边界和验收方式；信息不足时只追问会改变方案的关键问题。
3. 先检索再设计：
   - 在 `uiAssets[].paths` 中查找设计 token、组件 HTML、图片、图标和相似页面。
   - 在前端知识库中查找同业务模块、路由、页面文案和已有实现。
   - 需要系统检索时遵循 `knowledge-search` Skill 的分阶段检索流程。
4. 优先复用已有组件。HTML 组件可复制到当前项目后封装为 Web Component；保留其输入、事件和样式边界，不直接引用 `.external/` 路径。
5. 没有可复用资产时再补新组件，并沿用命中的 token、间距、字体、颜色和交互模式。
6. 覆盖正常、空、加载、失败、禁用等必要状态；不要只实现静态首屏。
7. 完成后列出复用的资产路径、新增内容和仍需确认的差异。

## 约束

- 资源包只读；需要发布的组件、图片、字体和样式必须复制到当前项目并使用相对路径。
- 不凭空发明品牌样式。没有视觉依据时，以现有资产和代码为准，并明确未还原部分。
- 不为了展示效果引入大型依赖；优先使用项目现有技术栈和原生 Web 能力。
- 结论必须能追溯到具体资产或代码路径。
