## §三类审阅检查项

### 风格审阅
- 标出难懂、过长、黑话多、概念跳跃、重复或标题不匹配的段落
- 给出**可直接替换**的改写建议
- 结构不合理 → 建议新章节顺序

### 业务审阅
重点检查：

- **角色与场景**：谁在什么条件下触发，谁受影响
- **主链路**：入口 / 操作 / 状态变化 / 结果展示 / 通知 / 记录
- **异常链路**：失败 / 撤销 / 超时 / 重复提交 / 权限不足 / 数据缺失
- **兼容链路**：老数据 / 老入口 / 老流程 / 多端 / 多版本 / 灰度回滚
- **周边协作**：运营配置 / 客服 / 风控 / 财务 / 埋点报表 / 下游系统
- **知识库一致性**：是否和 `.external/<alias>/` 既有规则冲突

### 文字流畅度审阅
- 上下文连贯吗？前一节的"输出"是不是后一节的"输入"？
- 抽象概念有没有具体例子兜底？
- 章节标题和内容匹配吗？
