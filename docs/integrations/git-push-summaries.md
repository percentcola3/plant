# 推送与文档变更记录

应用内统一 push hook 覆盖：保存/自动同步 saga、普通工作区保存、创建远端分支、团队空间推送（含重试）、通用 git push 封装。

流程：读取待推送的准确 commit 与远端分支当前 commit → 固定 SHA 推送 → 成功后调用当前 AI 引擎总结 → 将整体说明及逐文件说明保存到 Git notes → 单独同步记录。

记录存放在 `refs/notes/peeka-push`，每条 JSON 为一行，附在实际推送的 commit 上。记录包含推送时间、目标分支、前后 SHA、提交作者、文件路径（含重命名来源）、整体和逐文件说明。不会改写 commit，也不增加工作树文件或暂存用户草稿。

界面：历史版本 → 推送记录；Markdown 和项目文件预览工具栏 → 变更记录。可以按文档或目录筛选。读取记录时自动 fetch notes；失败时保留本地记录并提供重试同步。历史从 notes 自身读取，因此强推/rebase 后仍可查看早先的推送记录。

- 使用 AI 助手当前配置：Peeka 官方/内网代理，或 DCC/Claude Code。总结任务只接收已提交 diff，不开放工具，也不运行 Git 项目的指令文件。
- AI 最多等待 30 秒。未配置、网络失败、返回格式无效时保存明确标记的“基础变更记录”；代码推送不会因此失败。
- 代码 push 失败时不调用 AI、不写成功记录。代码成功但 notes 被远端拒绝时单独提示，可重试 notes，不重复推送代码。
- 多用户 notes 使用 `cat_sort_uniq` 合并并普通推送，冲突时拉取再合并重试，不强推其他用户记录。
- 为控制耗时，一次记录最多 300 个文件；AI 最多读取 20 个文本文件、36,000 字符 diff。大文件、二进制、锁文件及敏感凭证文件仅记录路径和变更类型；截断会在界面注明。
- 历史查询最近 500 次 notes 变更，每次最多展示 30 条匹配记录。旧版本不会自动补 AI 总结。
- 本次实现是应用内生命周期 hooks，不安装/覆盖 `.git/hooks` 或修改 `core.hooksPath`；终端手动 push 不会自动触发。普通 Git 用户可使用以下命令同步和查看记录：

```sh
git fetch origin refs/notes/peeka-push:refs/notes/peeka-push
git log --show-notes=peeka-push
```

验证使用临时 bare remote + 两个 clone，不会连接真实业务远端；覆盖共享、文档筛选、失败隔离、并发合并和暂存区保护。
